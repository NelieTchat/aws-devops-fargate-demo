Overview

What this project covers

This is a deliberate, well-documented reference for the full Fargate deployment lifecycle. Not a quickstart — a production pattern. Every layer is separated: the application, the container, the infrastructure, and the delivery pipeline. Each can be understood and modified independently.

  • Full stack, clearly separated — Node.js app → Dockerfile → Terraform IaC → GitHub Actions pipeline. Each layer is explicit, not magic.
  • Terraform-provisioned infrastructure — ECS cluster, task definition, service, ALB, target group, and security groups all declared in HCL. No console clicking.
  • Automated deploy on merge — GitHub Actions builds the image, pushes to ECR, and triggers a new ECS deployment. Zero manual steps after code review.
  • Progressive hardening path — repo is structured to show the upgrade path from a working default-VPC setup to private networking, Secrets Manager, and CloudWatch monitoring.
  • Clean, readable codebase — written as a reference others can learn from, not just a project that runs.

CI/CD Pipeline

Merge to deployed in one pipeline

Every merge to main triggers the full pipeline — build, scan, push, deploy. No manual steps, no console access required.

# .github/workflows/deploy.yml on: push: branches: [main] env: AWS_REGION: us-east-1 ECR_REPO: fargate-demo-app ECS_CLUSTER: fargate-demo-cluster ECS_SERVICE: fargate-demo-service jobs: build-and-deploy: steps: - name: Configure AWS credentials uses: aws-actions/configure-aws-credentials@v4 with: role-to-assume: ${{ secrets.AWS_ROLE_ARN }} aws-region: ${{ env.AWS_REGION }} - name: Login to Amazon ECR id: login-ecr uses: aws-actions/amazon-ecr-login@v2 - name: Build Docker image run: | docker build -t $ECR_REPO:${{ github.sha }} ./app - name: Tag and push to ECR run: | docker tag $ECR_REPO:${{ github.sha }} \ ${{ steps.login-ecr.outputs.registry }}/$ECR_REPO:${{ github.sha }} docker push ${{ steps.login-ecr.outputs.registry }}/$ECR_REPO:${{ github.sha }} - name: Deploy to ECS Fargate run: | aws ecs update-service \ --cluster $ECS_CLUSTER \ --service $ECS_SERVICE \ --force-new-deployment
Progression Path

Built to grow with you

The repo is structured as a progressive reference — each stage builds on the last, showing how a basic working deployment evolves into a production-hardened architecture.

🚀

Default VPC scaffold

Working Fargate deployment, ECR, ALB, and full CI/CD pipeline. Ships fast, proves the pattern.

🔒

Private networking

Move to private subnets with NAT gateway. Containers no longer have public IPs.

🔑

Secrets Manager

Environment variables replaced with Secrets Manager references. No secrets in task definitions.

📊

Monitoring + alerts

CloudWatch dashboards, container insights, and alerting for CPU, memory, and request errors.

Key Takeaways

What this project demonstrates

Terraform → ECS

How to express a complete ECS Fargate service — cluster, task definition, service, ALB, IAM — entirely in Terraform with no manual steps.

ECR lifecycle

Image tagging strategy using git SHA for traceability. Lifecycle policies to cap ECR storage. Scan-on-push for baseline vulnerability detection.

GitHub Actions + AWS

Wiring GitHub Actions to AWS using IAM roles (OIDC or access keys), managing ECR auth, and triggering ECS rolling deployments from CI.

Progressive hardening

How to structure a Terraform codebase so that security upgrades (private networking, secrets management) can be layered in without a full rewrite.
